SPACE DOCK — SPACE PARKING LOT KIT
===================================

Source / build
--------------
All raster pieces and mockups are generated by generate_kit.py with Pillow.
The compositor works at logical 1x pixels, then enlarges with strict
Image.Resampling.NEAREST only. No anti-aliasing is used.

  mockA_phone.png  1080 x 2340 = 360 x 780 logical pixels, 3x
  mockA_ipad.png   1640 x 2360 = 410 x 590 logical pixels, 4x
  mockA_wide.png   2560 x 1600 = 640 x 400 logical pixels, 4x
  mockB_phone.png  1080 x 2340 = 360 x 780 logical pixels, 3x
  mockB_ipad.png   1640 x 2360 = 410 x 590 logical pixels, 4x
  mockB_wide.png   2560 x 1600 = 640 x 400 logical pixels, 4x

mock_phone.png, mock_ipad.png, and mock_wide.png are also refreshed aliases
of the horizontal A variant so existing kit consumers remain reproducible.

Piece sizes
-----------
All pieces are authored at 1x. Transparent pieces are RGBA; deck pieces are
also RGBA so they can be composited over a scrolling lot background.

  kit/bay_floor.png       96 x 128 RGBA   A bay deck, nose-UP default
  kit/bay_back.png        96 x  24 RGBA   A service wall / clamp / stop
  kit/bay_divider.png      8 x 128 RGBA   thin A seam overlay
  kit/lane_tile.png       96 x  48 RGBA   A horizontal lane, tileable X/Y
  kit/lane_arrow.png      48 x  48 RGBA   A traffic arrow, points DOWN
  kit/bay_highlight.png   96 x 128 RGBA   A low-glow selection overlay

  kit/bay_floor_h.png    128 x  96 RGBA   B bay, rotated 90° from bay_floor
  kit/bay_back_v.png      24 x  96 RGBA   B outside service wall
  kit/bay_divider_h.png  128 x   4 RGBA   B row seam across a bay
  kit/bay_divider_v.png    4 x  96 RGBA   B short vertical seam/cap
  kit/lane_tile_v.png     48 x  96 RGBA   B vertical lane, tileable Y
  kit/lane_arrow_up.png   48 x  48 RGBA   B exit arrow, points UP
  kit/bay_highlight_h.png 128 x  96 RGBA   B low-glow selection overlay

  kit/lot_edge_left.png   16 x  96 RGBA   vertically tileable outer edge
  kit/lot_edge_right.png  16 x  96 RGBA   mirrored right outer edge
  kit/number_stencils.png 120 x  16 RGBA   ten 12 x 16 clean digit cells
  kit/lot_sign.png       192 x  32 RGBA   optional SPACE DOCK / LOT plate

The two ship sheets in ref/ are extracted into kit/ships/ at 84 x 112 RGBA
canvas size. The visible ship art is kept near 76 px across, roughly 75–80%
of the bay's short side in both orientations.

Horizontal layout A
-------------------
The bay coordinate system is 96 wide x 128 high. The default bay floor is
nose-UP and backed into the bottom edge. For this orientation:

  bay centre / ship canvas: (48, 64)
  ship canvas placement:    (6, 8) for the 84 x 112 ship canvas
  bay_back placement:       (0, 104)
  number anchor:             (7, 106), a 24 x 16 two-digit sprite
  highlight placement:      (0, 0)

For a row facing DOWN, rotate bay_floor, bay_back, bay_highlight, and the ship
180° with nearest-neighbour rotation. Place bay_back at (0, 0) after rotation.
This leaves each row backed-in toward the outside edge and the nose toward the
shared horizontal drive lane.

  * Side-by-side bays use x = lot_x + column * 96 with no gap.
  * bay_divider is placed at x = bay_x - 4. Its painted seam is only 1–2 px.
  * Row pitch is 176 px: 128 px bay + 48 px horizontal lane.
  * Tile lane_tile across the full bay span. Its amber dashed centre line is
    y = 22..25 and repeats every 24 px in X.
  * Place lane_arrow at the lane centre. Use lane_arrow_up for the reverse row
    direction. The mock A rows alternate DOWN and UP traffic.
  * Repeat lot_edge_left/right down the screen outside the bay span.
  * Compose bay numbers from two cells in number_stencils: 01 through 16.
    They sit at the service-wall end, not over the ship nose.

Vertical layout B
-----------------
The B bay coordinate system is 128 wide x 96 high. It is made from the A bay
rotated exactly 90° with nearest-neighbour pixels. A 304 px lane-group is:

  128 px left bay + 48 px vertical lane + 128 px right bay

Each vertical lane runs top-to-bottom. The left column's ship is rotated 270°
(clockwise) so its nose points RIGHT into the lane. The right column's ship is
rotated 90° (counter-clockwise) so its nose points LEFT into the lane. The
corresponding bay_floor_h is rotated/mirrored the same way. The outside wall
uses bay_back_v at x = 0 for a left bay and at x = 104 for a right bay.

  bay centre / ship canvas: (64, 48)
  rotated ship canvas:      112 x 84, placed at (8, 6)
  bay_back_v:                left at (0, 0), right at (104, 0)
  number anchor:             left (1, 5), right (103, 5), 24 x 16
  highlight placement:      (0, 0)

  * Tile lane_tile_v at x = lane_x and y from the scroll viewport downward.
    Its lane centreline is x = 22..25 and repeats every 24 px in Y.
  * Place lane_arrow_up on the lane centreline. Arrows point toward the top
    exit, where a ship pulls out, turns, and drives away.
  * Stack bay rows on a 96 px vertical pitch. Put bay_divider_h at each row
    seam; it is a 1–2 px painted deck line, not a pillar.
  * Centre the complete lane-group(s) horizontally. Never stretch bays or
    lanes; any leftover width stays at the side edges.
  * B responsive counts in the supplied mocks: phone = 1 lane / 2 columns,
    iPad = 1 lane / 2 columns, wide desktop = 2 lanes / 4 columns.
  * Compose all labels from two clean stencil cells so 01..16 remain legible.

Responsive mock content
-----------------------
Both variants use the two reference ship families plus dark silhouettes for
locked bays, and one selected bay with a thin cyan highlight. The header is
the minimal text “STAR DUST 102  SPACE DOCK · TAP A SHIP”. The footer is a
dedicated band below the scroll viewport containing only “Back” and
“Lift-off” labels. There are no thick UI boxes over ships.
